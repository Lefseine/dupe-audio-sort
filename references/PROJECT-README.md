# DupeScope · 同曲甄别 + 顺序修正

两件事，一个本地网页应用：

1. **版本甄别**：把散落在多张专辑里的同一首歌找出来，自动比一遍硬指标，告诉你该留哪版。
2. **顺序修正**：把《同一首歌》这种「歌名+歌星.wav」文件夹排出人能预期的顺序，并写成播放器真能读的顺序。
3. **位对齐 · 响度**：用整盘 cue 做 AccurateRip 逐位校验（唯一能证明"抓轨没错的"手段）；
   用 rsgain 量出整库响度，消除"响的显得好"的比较偏差。

全程本地、免费、开源，不依赖 JRiver 开机；Spek / CUETools 保留作人工目视复核（一键从界面调起）。

## 快速开始

```
双击 run.cmd            →  自动装依赖并打开 http://127.0.0.1:8765/
```

- 命令行指定端口：`run.cmd --port 9000`
- 直达扫描：`http://127.0.0.1:8765/?auto=D:\Music`（可存成书签，`&open=0` 自动展开第一组）
- 直达排序：`http://127.0.0.1:8765/?tab=order&dir=D:\Music\同一首歌`
- 直达位对齐：`http://127.0.0.1:8765/?tab=tools&dir=D:\Music\专辑目录`
- 右键菜单：`tools\install-menu.cmd`（只写 HKCU，`remove-menu.cmd` 可撤）

默认只对「同一首歌有多个版本」的文件做深度分析，其余文件只读元数据——
全库首扫之后结果进缓存（`.cache/analysis.db`），之后只算新增/改动过的文件。

## 比什么

| 指标 | 来源 | 识破什么 |
|---|---|---|
| 频谱上限 (kHz) | 本地 FFT（分频带积分 + 断崖检测） | 假无损、有损转无损、升频假 Hi-Res |
| 有效位深 | 定点网格反推 LSB | 无抖动的 16→24 升位 |
| DR 动态 | TT DR Meter 同口径（3s 分块波峰因数） | 响度战争型重母带 |
| LUFS / LRA / 真峰值 / PLR | ffmpeg ebur128 | 过响、削波失真风险、母带余量 |
| 削波样本数 | 全轨逐样本统计 | 削顶的烂母带 |
| 窄带缺口密度 | 2–16 kHz 谱底扫描 | 有损编码残留指纹 |
| 声道相关系数 | 整轨 ΣLR/√(ΣL²ΣR²) | 单声道复制成双声道、左右反相 |
| 直流偏移 | 整轨样本均值 | 转录/抓轨引入的 DC，白占动态余量 |
| 解码完整性 | ffmpeg 解码报错条数 | 坏块、截断 |

综合分 = 频谱真实度 35 + 位深/采样率 20 + 动态 25 + 峰值余量 10 + 无削波 10，
每一项在界面里单列，不给黑箱总分。

> 频谱与动态之外还该看什么、对应哪些免费工具，见 **[docs/OSS-TOOLCHAIN.md](docs/OSS-TOOLCHAIN.md)**。

## 位对齐与响度（第三个标签页）

### 位对齐 —— 比参数更根本的一层

前面所有指标都只能说明"听起来像真的"，**只有位对齐能证明这份抓轨和全网其他人的逐位一致**。
实现的是 AccurateRip v1/v2 全流程（纯 Python，可并发、可缓存、离线也能算本地部分）：

1. 解析整盘 `.cue` 的 TOC → 算 discID；
2. 逐轨解成 16-bit/44.1k PCM，算 v1（1 基位置加权求和）和 v2（64 位乘积高位折回）校验和；
3. 查 `www.accuraterip.com`，比对所有提交，取最高 confidence。

结果四态：`ok`（逐位一致）/ `mismatch`（有轨不一致，抓轨可能出错或经过重编码）/ `not_found`（小众碟库里没有）/ `need_cue`（无整盘 cue）。

> **硬边界**：AccurateRip 靠整盘 TOC 算 discID。**单曲 WAV/FLAC 没有 TOC，物理上无法校验**，工具会明确提示而不是给个假结果。
> 另外要求 16-bit 立体声、抓轨时已做过驱动器偏移校正——这些是 AccurateRip 协议本身的要求。
> CUETools 可一键拉起做 GUI 目视复核（`/verify` 会自动校验；官方说明它完成后不自动关闭，需手动关）。

命令行：

```
python -m dsc.accuracy "D:\Music\专辑目录"          # 找 cue 并联网校验
python -m dsc.accuracy "D:\Music\专辑目录" --no-net  # 只本地算 discID，不联网
```

### 响度归一 —— 消除"响的显得好"

比较不同版本时，响的那版会天然占便宜。rsgain 把每条曲目的 LUFS 和建议增益量出来，
让比较回到同一响度基准。随包已放入 **rsgain 3.8 官方便携版**（GPL，免安装，只写标签不动音频流）。

- **默认只读扫描**：在临时副本上跑，原目录零改动；输出每曲 LUFS / 增益 / 峰值。
- **确认后才写标签**：写的是标准 ReplayGain 2.0 标签，JRiver / foobar / 手机播放器都能自动应用；
  只改标签、音频流不变，随时可用 rsgain 重写撤销。
- 目标响度可选 −18 LUFS（ReplayGain 标准）或 −23 LUFS（EBU R128 广播）。

命令行：

```
python -m dsc.gain "D:\Music"                 # 只读扫描，出建议
python -m dsc.gain "D:\Music" --apply         # 确认后写 ReplayGain 标签
```

## 播放顺序为什么会乱，怎么治

`《同一首歌》/歌名+歌星.wav` 这种文件夹，播放器往往按"文件进文件夹的先后"播，原因三条：

1. FAT32/exFAT 的目录是**按写入顺序追加的链表**，车载/便携播放器直接按目录条目顺序读；
2. WAV 的标签支持很差，播放器读不到 track number，只好退化成按文件名；
3. 文件名排序时中文按 UTF-8 字节比，得到的是码位序 —— 既不是拼音也不是笔画。

所以只能改"播放器用来排序的东西"。五种手段各治一类播放器，界面里可以一次勾选：

| 手段 | 治哪种播放器 | 代价 |
|---|---|---|
| 文件名加序号 `01 歌名 - 歌星.wav` | 按文件名/自然序排的（绝大多数） | 改名 |
| 写 `m3u8`(UTF-8 BOM) + `m3u`(GBK) | 支持列表的（车载、foobar、JRiver） | 多两个文件 |
| 写标签：WAV 同时写 RIFF INFO + ID3v2 | 按标签排的（JRiver、MusicBee） | 改文件内容 |
| 按目标顺序设时间戳 | 按"日期"排的（部分车载） | 改文件时间 |
| 按目标顺序复制成 `_有序副本` | 按目录条目顺序读的 FAT/exFAT 设备 | 占一份空间 |

安全边界：默认**只出方案**；点「应用」并二次确认才动文件；**从不删文件**；
目标名冲突就跳过并报告，不覆盖；每次应用在 `.dupescope/undo-*.json` 落撤销清单，可一键倒回。

命令行同样可用：

```
python -m dsc.order "D:\Music\同一首歌"                     # 只看方案
python -m dsc.order "D:\Music\同一首歌" --apply --tags      # 执行：改名 + 列表 + 标签
python -m dsc.order --undo "D:\Music\同一首歌\.dupescope\undo-20261113-163631.json"
```

## 已知边界（诚实声明）

- **有效位深识不破加抖动的假 24bit**：重采样时加了 dither，低位就被填满了。
  这类文件靠频谱截止 + 升频检测兜底。
- **DR 低 ≠ 音质差**：有些老录音本来就是高压缩母带，低 DR 是它的原貌。
- 频谱截止读数可能与 Spek 目视差 ~1 kHz：我们取的是 -50 dB 频带电平边界，
  Spek 是肉眼看"最后一条可见亮线"，口径本就不同。界面提供一键 Spek 复核。
- DSD（dsf/dff）会先转 176.4 kHz PCM 再分析，位深检测对 DSD 不适用。
- **声道相关 ≈1 不一定是坏事**：单声道时代的老录音本来就左右相同，这是原貌；
  只有"标称立体声却完全同相"才值得怀疑。
- **解码报错数依赖 ffmpeg 的报错粒度**：0 条不等于绝对完好，细粒度损坏要靠 `flac -t` / CUETools。
- 排序改的是"播放器用来排序的东西"，不是播放器本身：极端固化的固件（把顺序写进私有库、
  或按文件系统物理块序读）仍可能不买账，此时只能用 `_有序副本` 整体替换。

## 架构（ADR 摘要）

- **ADR-1 自带解码引擎，不驱动 Spek**：Spek 0.8.2 是纯 GUI、无命令行参数，
  自动化只能自己算 FFT。收益：可并发、可缓存、数值精确到 0.01 kHz；代价：读数口径与 Spek 不完全一致（已文档化）。
- **ADR-2 不依赖 JRiver，DR 本地重算**：JRiver 的 DR 存在私有库里，MCWS 需要它常驻。
  本地按 TT DR 口径重算，跨版本可比性才是目的；留了 MCWS 适配层的位置（`dsc/` 新增模块即可）。
- **ADR-3 两遍解码**：主通道流式算 DR/削波/位深/频谱，副通道 ebur128，并发执行，内存恒定。
- **ADR-4 先分组后深挖**：元数据分组 → 只深挖多版本组。百 GB 库的成本从 O(全部) 降到 O(重复曲目)。
- **ADR-5 sqlite 缓存**：键为路径+大小+mtime，重扫接近零成本。
- **ADR-6 排序只改"排序依据"，不碰播放器**：播放器实现千差万别，唯一稳定的接口是
  文件名/标签/列表/文件时间/目录条目这五样。全部改一遍、任一播放器都能命中，
  比"适配某一个播放器"可维护得多；代价是文件会被改名，因此配套撤销清单。
- **ADR-7 拼音排序用 pypinyin，缺失时降级**：中文按码位排毫无意义，硬依赖会让便携性变差。
  所以 pypinyin 可选，缺失时退化并在界面明确警告，而不是静默给出错误的顺序。
- **ADR-8 位对齐自己实现 AccurateRip，CUETools 退为 GUI 复核**：CUETools `/verify` 官方说明
  "完成后不自动关闭、无法循环调用"，做不了百 GB 库的静默批处理；单曲文件又缺 TOC 算不出 discID。
  所以把可自动的部分（TOC→discID→checksum→查库→比对）用纯 Python 实现，可并发可缓存；
  CUETools 只作一键 GUI 复核。代价：口径要自己对齐 AccurateRip，且只覆盖有 cue 的整盘。
- **ADR-9 响度归一外挂 rsgain，默认只读**：ReplayGain 标签要能被 JRiver/foobar/手机真正读取，
  自算 LUFS 给不了这个跨播放器能力。rsgain 是 GPL 免费便携包（已随包），只写标签不动音频流。
  默认在临时副本上扫描、原目录零改动，写标签需二次确认——可逆性优先。

## 目录

```
run.cmd              双击入口
server.py            本地服务（标准库实现，无框架）
dsc/ffmpeg_bin.py    外部工具定位与自检
dsc/probe.py         元数据（ffprobe）
dsc/analyze.py       声学分析核心（频谱/DR/位深/削波/声道/DC/ebur128）
dsc/group.py         同曲归并 + 评分
dsc/pipeline.py      编排（扫描/缓存/并发/进度）
dsc/order.py         播放顺序修正（排序/改名/标签/列表/时间戳/撤销）
dsc/accuracy.py      位对齐（cue TOC / AccurateRip v1v2 / 查库比对）
dsc/gain.py          响度归一（rsgain 只读扫描 / 写 ReplayGain 标签）
dsc/report.py        HTML/CSV 导出
web/index.html       单页界面（版本甄别 / 播放顺序 / 位对齐·响度 三个标签页）
tools/bin/           便携 ffmpeg
tools/rsgain/        便携 rsgain 3.8（GPL，只写标签）
tools/shellmenu.py   右键菜单安装器（HKCU）
docs/OSS-TOOLCHAIN.md 免费/开源工具链调研
test/gen_fixtures.py 造"已知答案"样本，回归验证用
reports/             每次分析的 HTML/CSV 报告
```

## 依赖

Python 3.10+（run.cmd 自动建依赖）、numpy、rapidfuzz、mutagen、pypinyin、ffmpeg（已随包）、
rsgain 3.8（已随包，GPL）。Spek / CUETools 可选（人工复核按钮用，没装不影响分析）。
pypinyin 缺失时中文退化为码位序（界面会警告）。
